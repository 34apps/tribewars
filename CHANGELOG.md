- 2026-11-04 (`0a043e2`) — Multiple worlds, part 2: the lobby (one account, many worlds; `docs/MULTI_WORLD.md`). New `apps/lobby` (Fastify + `node:sqlite`, bundled like the server, own `Dockerfile.lobby`, data `/srv/clanfire/lobby`): accounts (scrypt, same hash format as the worlds), hashed-token sessions (cookie `tw_lobby`, `Path=/lobby/`), the multi-account IP guard (moved here), world list (open/full/closed + public path), admin CLI (`keygen`, `worlds`, `world-add/status/rename/remove`, `shared-ips`, `ban/unban/grant/revoke`), backup, and the one-time `npm run lobby:import -- <world db>` (backs up both databases first, copies players as accounts with the same name + password hash, writes `players.account_id`; idempotent; name conflicts reported, exit 2). `POST /lobby/api/worlds/:id/enter` returns an Ed25519 pass (account id, name, world id, chieftain, staff role, 60 s, random nonce) signed with env `LOBBY_SIGNING_KEY`. Worlds started with `LOBBY_PUBLIC_KEY` (comma list = key rotation) accept `POST /w/<id>/api/auth/enter {pass}`: signature, world id, expiry, lifetime cap and a one-time nonce kept in the world DB until expiry; first entry creates the player (`players.account_id` unique, schema v2), later entries sign in the same one; staff role copied from the lobby at every entry; their own register/login answer 403. Without the key everything works as before (dev, tests, preview). World info gained `lobby: boolean`. Web: lobby sign-in/register (same look, chieftain step kept), world picker with status badges and Play (pass posted in the body to the world, then `/w/<id>/`), "Worlds" link in the account menu, signed-out world pages go to `/lobby/` when the world is lobby-only, path validated against open redirects; Vite proxy for `/lobby/api`. Deploy: `lobby` compose service (no published port), Caddy `/lobby/*`, `lobby` pseudo-world in `update/backup/restore/rollback.sh` (+ `all`), CloudFront `/lobby/api/*`. **Security gate:** ownership (a pass only ever yields the player linked to its signed account id; never linked by name — an unlinked same-name player is refused 409), input schema (strict ajv bodies, pass ≤ 2 KB checked before parsing, strict claims), rate/caps (per-IP register/login/enter, per-account enter 20/min, global limits), no leaks (same 401 for unknown user/wrong password, ban only told after the right password, key never logged or in errors), server-side timing (60 s pass, ≤ 120 s accepted lifetime, ±10 s skew, nonce one-time), multi-account abuse (IP guard in the lobby, world still records IPs for staff tools), audit (lobby audit log; world `register`/`enter`/`role_sync`/blocked rows), tests. Residual: a lobby ban stops new passes only (live world sessions last until expiry or a world ban); a leaked signing key forges any pass (rotate). Players: same speed; one account for every world. Tests: lobby 62 (incl. end-to-end lobby→world and import→pass), server +27 (`lobby-entry.test.ts`, deploy-config), web +10. Check (engine 223, lobby 62, server 283, web 19) + `npm run build` (now also bundles the lobby) + preview build pass. Not run here: Docker build, compose, shell scripts (`bash -n` denied), a real browser view of the lobby/picker (layout checked by reading CSS: 1 column at 360 px, 2 from 640, 3 from 1000).
